# 企业知识库设计

企业资料库登记审核后的规范、工法和历史案例。当前投标项目的招标文件、答疑及图纸由 WF01 归入独立项目档案。`KnowledgeStore` 会拒绝带在办 `project_id` 或非 `enterprise` 范围的通用知识登记。

| 分类 | 资料与切片 | 第一阶段引用规则 |
| --- | --- | --- |
| KB01 国家法规及工程规范 | 按条、款或规范章节切片，保留条号或页码、原件版本与生效日。 | 检索已发布且在有效期内的适用版本。适用性由审核人员确认。 |
| KB02 招标文件范本 | 按条款及模板章节切片，保留范本类型与适用地区。 | 可参考形式，结果标记 `reference_only`。 |
| KB03 企业施工技术方案 | 按工序和方法切片，记录适用专业、项目类型、工艺和规模。 | WF06 按章节检索，技术人员复核与本项目的适用性。 |
| KB04 企业历史投标文件 | 按章节提取经过审查的可复用案例，保留历史项目名与版本。 | 标记 `reference_only`，工程参数、人员、工期及工程量以当前项目核准事实为准。 |
| KB05 企业工程业绩 | 源合同、验收证明和结构化业绩档案。 | WF05 从独立企业证据表查询。 |
| KB06 企业资质和人员 | 证照、人员状态及有效期。 | WF05 从独立企业证据表查询。 |
| KB07 企业管理制度及编制标准 | 按制度章节或操作规程切片。 | 可作为章节编制参考。 |
| KB08 企业造价及成本参考 | 按工作表、成本业务字段及来源版本登记。 | 预留分类，技术标检索排除此类资料。 |

同一资料以 `key` 标识，原件发布的版本写入 `source_version`，系统另分配递增的 `version`。登记时提交文件名称、来源引用、原件 SHA-256 和资料密级。元数据列出文件类型、项目名称、项目类型、行业、专业、地区、规模和工艺。未知字段留空，明确通用时填写 `通用`。每个切片都携带真实页码或章节、条款、工作表、表格、图号等位置。仅适用于纯文本时，系统可以按段落生成定位。登记人员负责提交原件的真实哈希，审核时将其与原件重新核对。

新版本以 `draft` 保存。审核通过并且进入有效期后发布，之前的已发布版在同一数据库事务内置为 `superseded`，引用仍可以按版本回查。被驳回、作废、尚未发布、已过期及跨租户的资料不会进入技术标检索。已审核的受限资料仍被技术标检索排除。规范的原版发生变化后建立新版本，保留原版定位及审查记录。变更、驳回、发布和作废均登记操作者、时间、资料编号和版本。

词法查找支持中文相邻字、英文词及编号等关键词。配置本地嵌入模型后，可在入库及检索时传入同模型的嵌入向量，执行余弦相似度排序或与词法分数加权重排。默认关键词模式可离线调试。地区、行业、专业、项目类型、规模、工艺在排序前过滤，明确登记的 `通用` 允许跨该项匹配。每条命中返回 `key`、资料版本、原件版本、原件哈希、来源、切片序号和定位。现有向量以 JSON 存储，由服务计算分数，适用于小批量试点。后续接 `pgvector` 或 Dify Dataset 时，仍需沿用业务库审核与版本门控。

WF05 的资质、人员、业绩、设备和体系证据各有类型与独立版本，查询要求当前审核版本、主体状态在用、有效期覆盖查询日期。资质和人员还需要有效截止日或经核准的永久属性。结构化证据是匹配候选，招标声明及所需附件仍要按本项目逐项确认。

Docker 初始化 SQL 只写入八个分类。接入时从有授权的少量工法、规范和历史项目资料开始，先检查版本和来源，再试跑检索。测试数据全部使用合成文本和演示编号。
