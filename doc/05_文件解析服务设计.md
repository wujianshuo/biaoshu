# 文件解析与成果导出

WF01 通过业务 API 调用本地文件解析模块。原件由项目档案保管，解析结果随文件版本保存。招标条款、知识引用和编制记录使用项目 ID、文件 ID、版本和定位信息追溯原件。

## 支持范围

| 格式 | MVP 解析行为 | 定位与复核 |
| --- | --- | --- |
| 可搜索 PDF | 使用 `pdfplumber` 提取逐页正文和识别到的有线框表格。表格按行保存单元格及边界坐标。 | `第 N 页` 和 `第 N 页 表 X 行 Y`。页码是 PDF 的物理页序。对复杂版面、跨页表、栏间顺序和图注以原件为准。 |
| 扫描 PDF、PNG、JPEG、TIFF | 配置本地 Tesseract 时使用本机 OCR。PDF 通过 PDFium 渲染无文字层的页面，TIFF 可逐帧识别。 | OCR 输出始终标记待复核。混排页面保留文字层，同时提示复核较大图像。未配置 OCR 时保留档案并提示补充可搜索原件。 |
| DOCX | 按文档顺序提取标题、段落和表格行。 | `段落 X`、`表 X 行 Y` 和最近的章节标题。Word 的物理分页取决于排版和渲染，`page` 留空。有图片、嵌入对象、文本框或嵌套表格时提示复核。 |
| XLSX | 按工作表读取单元格，保留原值、公式、缓存结果，以及数字格式 `0000` 一类的显示值。 | `工作表!A1:C1`。保留文本编码的前导零、空格和隐藏表状态。缺少公式缓存值时标记待复核，不执行公式，也不从外部工作簿取值。 |
| TXT | 读取 UTF-8、带 BOM 的 UTF-16 或 GB18030 文本。 | `第 X 行`，超长文本分段时追加段号。 |
| DWG、旧 DOC 和旧 XLS | 返回 `unsupported`，保留人工处理状态。 | 可由本地专业工具导出为 PDF、DOCX 或 XLSX，再与原件一起归档。CAD 图层、坐标、图形语义和其他旧格式另行扩展。 |

有加密、文件损坏、格式与扩展名不匹配等情况时，解析器返回可读的 `FormatError`。归档状态和失败详情由业务 API 更新。解析模块不发起任何网络请求。

## 解析契约

`parse_document(filename, data)` 返回 `format`、`status`、`snippets`、`warnings`。每段 `snippets` 有 `text`、`kind`、`locator`、`page` 和 `section`。表格段附带 `cells`，PDF 表格附带 `bbox`，XLSX 表格附带 `sheet_state`。

```json
{
  "format": "pdf",
  "status": "parsed",
  "snippets": [{"text": "合同工期112日历天。", "kind": "paragraph", "locator": "第 3 页", "page": 3, "section": null}],
  "warnings": []
}
```

- `parsed` 表示有可用文本且解析器未报告待核查项。
- `needs_review` 表示有 OCR、无文字层、缺缓存值或其他解析质量问题。保留已有提取结果和原因。
- `unsupported` 表示当前格式需要专用处理。可补充转换版或转录证据。

解析器限制单文件容量 32 MiB，PDF 1000 页。上传 API 默认每文件 25 MiB，实际限制取配置和解析上限的较低值。Office 包解压后上限 128 MiB、4096 个条目。表格累计扫描范围上限一百万格。OCR 单图不超过 1600 万像素，单文件最多处理 40 页，每页 60 秒。遇到超限文件应按项目资料原有版本关系拆分，并在归档记录中保留转换来源。

WF01 对有可用提取文字但需要复核的正文和补遗列出 `needs_parse_review`。审核人在对照原件后，通过 `resolutions.parse_confirmations` 按文件和版本确认，WF02 才采用相应内容。无可用文本的必要文件需补传可搜索原件或版本。

部署环境可配置 `BIAOSHU_OCR_BIN` 指向本地 Tesseract，并安装 `BIAOSHU_OCR_LANG` 指定的语言，默认 `chi_sim+eng`。测试环境做了 OCR 图像渲染和结果接入验证，中文 OCR 准确率由企业使用代表性扫描件验收。

## Word、Excel 和 PDF 导出

- `render_docx(title, chapters)` 使用内置 A4 模板，保留章节顺序、标题层级、Markdown 表格和项目符号。合并文档包含封面标题、目录域和页码。目录页码可在 Word 中更新域。章节内容为空时会在草稿中标注待确认。
- 使用指定 DOCX 模板时，`render_docx(..., template=bytes)` 将正文插入一个独立的 `{{BID_BODY}}` 段落。模板原有标题样式、固定表单和段落由编标人预设。
- `render_matrix(rows, title, fields)` 输出 `.xlsx`，保留编号、数值和空白，并冻结表头、提供筛选。来自招标材料或模型的文本按文字储存，即使以等号开头也不作为公式运行。
- `render_pdf(docx_data)` 使用 `BIAOSHU_SOFFICE_BIN` 指定的本地 LibreOffice。转换使用独立用户配置和临时目录，输出前校验 PDF 标识。含外部链接、复杂 Word 域、嵌入对象或宏的模板在自动转换时返回人工处理提示。未配置转换器时可下载 DOCX。

## 验证

运行 `python -m unittest discover -s tests -p test_formats.py -v`。测试使用内存生成的模拟原件，验证了实际 PDF 页码和表格、DOCX 顺序和字段、XLSX 多表与公式、编号前导零、原文作为文本导出，以及 CAD、扫描和 PDF 转换的状态输出。办事文件的最终排版、签章和交易平台要求按实际项目检查。本地未发现 LibreOffice，真实 PDF 转换与 Word 分页渲染待部署环境验证。
