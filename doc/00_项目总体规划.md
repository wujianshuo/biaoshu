# 项目总体规划

第一阶段面向施工企业的编标人和复核人，交付从招标资料入库到技术标审核稿的可追溯闭环。案卷、响应矩阵、评分项、企业证据、章节和交付文档均保留项目及版本信息。初版 Chatflow 和导入说明已作为基线独立存档，第一阶段功能位于 `biaoshu-mvp` 开发目录。

## 第一阶段交付

| 工作流 | 交付结果 | 人工责任 |
| --- | --- | --- |
| WF01 项目资料入库 | 项目、分类后的文件版本、解析摘要和资料档案 | 核对正文、补遗及待复核的解析片段 |
| WF02 招标文件解析 | 有原文出处的事实、要求、评分规则、指定章目和补遗说明 | 核对关键事实、来源及补遗替换关系 |
| WF03 招标要求分析 | 按否决、资格、技术、商务、格式分类的要求响应矩阵 XLSX | 跟进实质性要求、缺项和责任分工 |
| WF04 评标办法分析 | 评分响应矩阵 XLSX，记录明示分值、原文和待补材料 | 核查评分条件、材料及填报要求 |
| WF05 企业资料匹配 | 匹配报告、企业证据候选和来源版本 | 逐项确认采用的证据，记录缺失或待确认 |
| WF06 技术标编制 | 按章生成正文、DOCX 及来源记录 | 按项目要求和施工可行性审核及修订 |
| WF09 投标文件审查 | 逐项审查结果、阻断项和人工核对项 | 整改并审核关键要求、专项方案和版式 |
| WF10 文件组装 | 技术标 Word 草稿、审核稿和文件记录，可配置 PDF 转换 | 检查模板、目录、页码和最终文件版本 |

企业知识库先建设分类、来源、版本、生效时间、审核和检索能力。规范与工法按条款和工序入库，历史标书提取经审核的可参考做法，证照与人员等材料单独登记。当前项目的约束与工程参数从本项目确认过的材料读取。项目招标资料独立归档。

## 开发阶段

1. **核心 MVP。** 完成上述八个工作流、业务数据库、文件解析、局域网 API、项目工作台和技术标 DOCX。先用合成项目可重复试跑，再接本企业一套授权项目验证质量。
2. **商务资信扩展。** 从 WF05 的结构化证据和审核状态建设 WF07，接入企业原件、表单和证照有效期提醒。
3. **报价及交付扩展。** 建设 WF08、清单计算和造价审核，核验分册和综合组装。报价金额由程序计算并由造价人员确认。
4. **视觉和经验沉淀。** 评估 ComfyUI 辅助示意图、企业工法案例整理和审核结果反馈。工程图纸的尺寸、坐标和施工约束由专业工具和人员复核。

## 验收边界

技术标审核稿针对当前项目和来源版本生成。商务标、报价文件、签章、加密以及交易平台专用格式属于后续业务处理。首批试点宜选择同一主营专业、招标正文和补遗齐全的项目。由编标人事先标注关键响应条款和事实，检查引用定位、错填、漏提与人工复核时间。

八份 DSL 已通过官方节点字段和本机回环 API 契约检查。当前宿主的 Docker Desktop 受 Inference Manager 初始化故障影响，实际 Dify 界面导入和执行待实例可用后确认。真实企业文件、正式审核、私有模型工程效果和生产部署验收需使用企业授权环境完成。逐项记录见 [项目实施进度](12_项目实施进度.md) 和 [系统测试规范](09_系统测试规范.md)。
