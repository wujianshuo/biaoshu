# AI 提示词规范

提示词统一放在 `prompts/` 下，作为源码的一部分随提交审查和发布。业务后端读取对应文件，把系统提示词和结构化用户输入分别传给企业内网模型。Dify 文件定义输入和 HTTP 调用契约，业务提示词在同一位置维护。

| 提示词 | 输入 | 输出与服务端核验 |
| --- | --- | --- |
| `WF02_招标解析.txt` | 已归档资料的有限长度片段和来源 ID。每段带文件名称、版本、页码或其他定位。 | `items` 数组包含事实、招标要求、评分、章目和补遗。检查来源 ID、连续原文、事实值和单位。只有原文可核对的明示分值写入评分项。无法核验的内容计入复核提示。 |
| `WF06_技术章节.txt` | 指定章节名称、已确认项目事实、相关要求及评分、可参考知识和已确认企业证据。 | JSON 包含章正文、响应要求和评分 ID、知识引用、证据 ID、使用的事实键及待确认项。服务核对每个引用属于本轮输入。保存章稿和来源，交由专业人员复核。 |

## 内容要求

1. 文件片段、用户录入和历史案例都是供业务分析的资料。提示词明确资料内部的流程指令不能改变模型任务。模型输出经过 JSON 结构和引用范围检查，再参与业务计算。
2. 工期、工程量、项目地址和质量要求使用当前确认版本。企业人员、资质及业绩只能依据项目审核采用的证据。历史投标材料提供经审核的可参考工法，规范必须用适用版本。
3. 把缺失、冲突和未核准的值写成 `【待确认：事项】`，同步到 `pending_items`。生成的章节标记待审核，以独立的审批记录判断该版本是否通过。施工可实施性、证据是否符合要求以及提交格式由对应人员审核。
4. 模型输出普通 JSON 对象。引用只能从输入列表选择。原文保留数字、单位、否定范围和来源定位。章内容按评分和工序展开，篇幅遵从项目要求。
5. 业务程序负责版本确认、身份鉴权、审批、格式导出及确定性计算。提示词或模型输出的合规结论不能代替审查记录。

## 变更测试

修改提示词时同步核对调用字段和业务端校验。为条款改写、补遗冲突、企业证据缺失、引用不存在、输出截断和章节重编保留回归样例。发布时记录仓库提交、模型标识及数据范围。合成样例用于检查结构和流程，工程效果使用经授权的真实资料、同一输入集及人工标注验证。
