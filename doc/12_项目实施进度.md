## 仓库与环境

GitHub 私有仓库 `wujianshuo/biaoshu` 的 main 基线为 `4d136c457470bc6a83f0fdaae5b6ceaa1c03d12f`。检查时有第一版 Chatflow、导入说明和变更记录。Git CLI 没有可用的私有仓库凭据。第一阶段建立在从连接器核验的基线文件上，交付为独立工作目录和源码包。未推送或改动 GitHub main。

## 验证记录

- 八份 YAML 全部通过独立解析、生成一致性、Dify 1.7.2 官方节点模型和版本校验。包含 Start、Code、HTTP、End、WF01 条件和文件数组节点。八份 DSL 的本地 HTTP 契约模拟通过。
- 自动化测试使用合成项目文件。使用真实回环 HTTP 运行 FastAPI 后端，另一个回环服务提供可控的模型响应，调用顺序覆盖 WF01–WF06、WF09、WF10。验证了双文件上传、补遗工期冲突、人审、隔离、真实 XLSX 和 DOCX、旧知识引用的审核稿失效。
- 本机全套 23 项测试通过。PostgreSQL 18.6 WASM 引擎通过 Psycopg 建立实际 TCP 连接并复测数据库和八条业务链路。独立启动脚本也完成了配置初始化、SQLite 建库与实际 HTTP 健康检查。生产 Compose 目标是 PostgreSQL 16，正式部署后需按数据库文档复跑。
- MinIO 适配器使用真实 SigV4 签名和模拟 HTTP，通过私有桶策略、租户项目命名、摘要和内网连接检查。Compose 文件通过静态配置解析。真实桶、Compose 镜像构建和容器未在本机运行。
