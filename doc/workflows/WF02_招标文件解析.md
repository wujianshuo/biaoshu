# WF02 招标文件解析

DSL `workflows/WF02.yml`。开始节点接收 `project_id` 和可选的 `request_json.document_ids`。代码节点校验 JSON 及 ID 数组。HTTP 节点调用 `POST /v1/workflows/WF02/run`，解析结果节点从响应提取业务状态。结束节点返回 `status`、`http_status`、`result_json`。

后端读取该项目的资料及对应版本，按项目事实、招标要求和评分项进行结构化提取，保留原文位置。模型依据当前项目资料提取关键字段并标出不确定内容。补遗冲突交人工查看原件、选择有效事实并确认条款替代关系。企业历史文件不进入招标事实来源。

测试使用已审核档案和带来源的招标、补遗文件，确认工期等冲突在解决前保留标识。由审核人员在 `analysis/latest` 确认事实和补遗关系。已替代条款保留追溯记录。下游WF03、WF04只使用通过审核的分析快照。
