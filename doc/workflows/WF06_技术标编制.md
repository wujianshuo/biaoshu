# WF06 技术标编制

DSL `workflows/WF06.yml`。开始节点接收 `project_id`，可填 `{"chapter_ids":["现有章节ID"]}`。代码节点校验 ID 列表后，HTTP 节点调用 `POST /v1/workflows/WF06/run`。结果节点输出编制状态、章节引用和 HTTP 状态。

后端以审核过的项目要求、事实、评分和证据匹配为输入，确定目录。按每章的评分点选择适用知识版本和证明材料，再分别调用本地模型、保存草稿和引用依据。历史材料提供工法参考。项目特有参数和企业证明必须有来源，缺项由模型标记为待确认。审核人员逐个复核 `chapter/{chapter_id}`。新版本编制后重新审核受影响的章节。

测试先编制目录及章节，再以单个章节 ID 发起重编。检查其余章节未重编，正文能定位到当前项目原件，过审知识条目附带版本和来源，初稿保留待审核状态。超时后可查询章节记录，按缺失章节重跑。
