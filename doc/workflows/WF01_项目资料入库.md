# WF01 项目资料入库

DSL `workflows/WF01.yml`。输入 `project_id`、`request_json`，可附 Dify `files` 本地文件列表。`request_json` 可含 `project_name`、`industry`、`document_ids` 以及按原文件名索引的 `document_kinds`。可用类别为 `tender`、`amendment`、`drawing`、`boq`、`template` 和 `other`。

| 节点 | 输入 | 输出 |
| --- | --- | --- |
| 开始、校验请求 | 项目 ID、项目参数、内网基址 | `project_id`、`payload_json`、`request_body` |
| If-Else | `files` | 非空进入上传分支 |
| HTTP 上传 | 表单 `project_id`、`request_json`、重复的 `files` | 项目档案状态和记录引用 |
| HTTP 归档 | JSON 请求、新建信息或既有 `document_ids` | 既有资料归档或新项目的业务结果 |
| 结果校验、输出 | HTTP 状态和响应 | `status`、`http_status`、`result_json` |

后台对原文件进行格式辨识，保留版本、摘要及解析位置。上传后查看档案中的未识别和解析异常。文件角色由项目资料和人工审核确认，知识库检索不参与此步骤。

测试时项目 ID 留空，上传 `招标正文.txt` 和 `补遗一.txt`，参数使用 `{"project_name":"示例工程","industry":"房建","document_kinds":{"招标正文.txt":"tender","补遗一.txt":"amendment"}}`。检查档案是否包含两个文件版本及各自的解析质量。另测既有项目未附文件的调用。使用不同于提交人的审核身份审核 `archive/latest`。
