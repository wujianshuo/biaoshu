# 前端开发规范

第一阶段工作台与业务 API 同源部署，从 `/` 打开。使用浏览器原生 HTML、CSS 和 JavaScript，供企业内网的编标人和复核人处理单个项目。调用契约见 [接口文档](11_接口文档.md)。

## 操作顺序

1. 输入当前账号的业务 API 令牌。加载其有权访问的项目后，创建或选中一个项目。
2. 上传招标资料并按需确认文件类别。查看文件版本、解析状态和警告，生成 WF01 档案。扫描、图纸和解析失败需要有可定位的处理说明。
3. 按 WF02、WF03、WF04、WF05 和 WF06 顺序生成对应记录。显示记录类型、ID、版本、文件来源和当前审核状态。允许按章节 ID 发起重编。
4. 复核人通过独立账号查看记录，提交当前版本、审核意见和结构化确认项。对补遗有效性和冲突事实，以实际来源条款或文件版本为准。
5. 使用 WF09 检查缺章、缺证据、章节审批状态、关键事实及响应覆盖。使用 WF10 下载技术标草稿，并在人工确认后获取技术标审核稿。

页面显示后端返回的真实状态，包括待确认、已确认、退回和执行错误。请求进行中禁用同一动作。运行超时后先刷新项目记录，确认是否已生成结果，再决定是否重跑。后端返回版本冲突时保留用户填写的意见，刷新目标记录再提交。

## 数据和交互边界

- 令牌保留在页面内存中，重新加载后需重新输入。页面、URL、错误日志和下载文件中均不输出令牌。
- 项目资料、原文、后端错误及模型输出按文本展示。DOM 使用 `textContent` 填充数据。表格、按钮和文件名由受控组件生成。
- 角色和项目权限由 API 核验。页面根据角色提供相应操作入口，下载请求继续携带授权。更换项目时清空前一项目的结果和审核表单。
- 上传时展示文件名、资料类别和服务器反馈，遇到体量超限、文件类型不匹配或缺文字层时显示对应原因。使用中文标签，保留键盘操作和清晰可读的状态反馈。
