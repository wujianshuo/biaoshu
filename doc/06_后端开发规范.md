# 后端开发规范

后端使用 Python 3.12 和 FastAPI。入口 `biaoshu.app:create_app` 初始化配置和存储，并注册项目、文件、工作流、审核、知识与成果下载接口。部署和测试用同一业务入口。

## 模块职责

- `config.py` 解析环境配置和 Bearer 凭据，提供租户、账号、角色和项目范围。配置错误应在启动时提示。
- `app.py` 处理请求验证、上传限制、错误映射和下载。用 `/healthz` 检查服务与数据连接，模型已配置状态按运行环境返回。
- `workflows.py` 实现项目流程、审核和产物组装。编制保存前核对上游修订，审核应针对当前确切版本。
- `interpretation.py` 将解析段落变为可寻址来源，对模型摘录执行原文核验。补遗替换与冲突事实由审核人员确认。
- `knowledge.py` 管理知识来源、资料版本、生效状态、检索及结构化企业证据。章节只采用已发布的适用知识和本项目确认的证据。
- `formats.py` 解析文件并生成 DOCX、XLSX。可选 OCR 与 PDF 转换由本地工具完成，无法解析的格式返回可处理的状态。
- `store.py` 负责项目与记录读写、前置条件、事务和日志。`objects.py` 保管原件和产物，内容哈希用于完整性检查。

## 权限、版本和错误

| 场景 | 处理方式 |
| --- | --- |
| 身份与项目授权 | 每个业务请求从 Bearer 凭据解析身份和租户。数据库操作必须携带租户 ID，项目访问还要通过项目范围判断。 |
| 人工复核 | 编辑和复核分开授权。审批记录保存审批人、审核意见和目标修订。后端拒绝编制人复核自己的项目成果。 |
| 文件读写 | 上传后检查格式和大小，原件以对象摘要寻址。下载前鉴权并核对文件哈希，历史下载可显式指定修订。 |
| 同时编辑 | 调用记录更新传入 `expected_revision`。完成产物前检查依赖记录的 `preconditions`，批量写入由数据库事务提交。版本冲突时返回 409，用户读取新版本后再操作。 |
| 模型和外部解析器 | 配置地址、模型名和超时由环境传入。网络地址复核、解析异常和输出结构错误分别报告。失败的工作流保留执行状态，操作台按项目记录回查。 |
| 日志和机密 | 运行日志记录工作流、项目、运行 ID、状态和操作人。模型请求体、鉴权凭据和原文通过业务数据路径处理。日志按企业内网权限管理。 |

运行一次工作流可能创建多条版本记录。调用超时先按项目和记录类型查询现状，再根据缺失项补跑。逐章重编使用 `chapter_ids` 缩小影响范围。HTTP 状态码与请求参数见运行实例 `/openapi.json` 和 [接口文档](11_接口文档.md)。
